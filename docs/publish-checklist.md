# publish-checklist.md

記事のステータスを`ready`にする前に使う最終チェックリストです。判断基準は[PROJECT_PRINCIPLES.md](./PROJECT_PRINCIPLES.md) / [CLAUDE.md](../CLAUDE.md) / [BRAND.md](../BRAND.md)に従います。

## 運用ルール

各項目は以下のいずれかで管理します。

- `[x]` 確認済み
- `N/A(理由)` 記事の内容上、該当しない(理由を必ず添える)

該当する項目がすべて確認済み、かつN/A項目すべてに理由が書かれている場合のみ、ステータスを`ready`に変更できます。理由のないN/A、および未チェック(`[ ]`)が残っている場合は`ready`にしないでください。

## インタビュー・事実性

- [ ] なぜ作ろうと思ったか / 解決したかった問題を聞いている
- [ ] 失敗したこと・改善したこと・今ならどう作るかを聞いている
- [ ] ユーザーが回答していない体験・測定結果・使用感を創作していない
- [ ] 未確認の情報には「未確認」「要検証」と明記している
- [ ] 製品仕様・価格など変化しうる情報を公開前に最新確認している

## 初心者向けの分かりやすさ

- [ ] 専門用語に一言説明を添えている
- [ ] BRAND.mdのトーン&ボイス(伴走する語り口、失敗談を隠さない)に沿っている
- [ ] 上から目線・マウンティングになっていない

## 技術・安全

- [ ] サンプルコードに処理内容がわかるコメントがある
- [ ] コードが可能な範囲でコンパイル可能な状態になっている
- [ ] 使用ライブラリ・対応ボード・必要バージョンを明記している
- [ ] 電圧・電流・極性・発熱・ショートの注意点を記載している
- [ ] 5V系/3.3V系の混在がある場合、安全性を確認・明記している
- [ ] 未実機検証のコードには「未実機検証」と明記している
- [ ] 配線図・フローチャートが必要な箇所に用意または提案されている

## SEO

- [ ] タイトル・見出しに読者が実際に検索するキーワードを含めている
- [ ] 1記事1検索意図になっている(CONTENT_PLAN.mdの検索意図と一致しているか)
- [ ] 記事冒頭で読者の疑問に早く答えている

## アフィリエイト(Affiliate Gate)

- [ ] **記事を公開する前に、実際に使用した商品が登場するかを確認したか**(登場する場合は、商品名・
  型番・ASIN・Affiliate化する価値・CTA位置の4点を評価する。ASINが未確認の間はCTAを追加しない)
- [ ] **ASIN・型番が「実際に使用した商品と同一」と確認できているか**(型番や見た目が似ている、
  同じカテゴリの製品というだけでは不十分。過去に、記憶だけで「使用したのはAI-Thinker製の
  ESP32-CAM」と記載したが、後日Amazon購入履歴で確認したところ実際はFreenove製だったという
  訂正が発生している。ブランド名・型番は記憶だけで断定せず、購入履歴等の一次情報で裏付けが
  取れるまでは`used=true`にしない)
- [ ] 紹介する商品が読者の課題解決に必要なものだけになっている
- [ ] 商品紹介が記事の主目的になっていない
- [ ] 実際に使用していない商品を使用済みのように書いていない(`used=false`のCTAに断定的な推奨表現がない)
- [ ] 比較記事の場合、選定基準・対象読者・メリット・デメリットを記載している
- [ ] 不自然な箇所にAmazonリンクを無理に入れていない
- [ ] 商品リンクは`{% include amazon-cta.html %}`経由で、本文へ`<a>`タグやアフィリエイトURLを直書きしていない
- [ ] `affiliate_products`がある記事に、affiliate disclosure(記事単位)が表示される状態になっている
- [ ] 商品の現在価格・在庫状況を本文に記載していない(Amazon側で確認する導線にしている)
- [ ] 原則1商品1CTA程度を基本とし、同一商品を記事内に大量配置していない

## GitHub運用

- [ ] サンプルコードが整理されている
- [ ] README更新が必要な場合は提案している
- [ ] コミットメッセージを提案している

## 公開前の技術チェック(Publication Gate)

- [ ] frontmatterに`title`/`status`/`permalink`/`order`/`description`が揃っている
- [ ] 画像すべてに`alt`が設定されている
- [ ] 本文中の画像・内部リンクが`relative_url`を使っている
- [ ] 本文中にH1(`# `見出し)が存在しない
- [ ] レスポンシブ表示を崩す要素がない(表・CTA等)
- [ ] `git diff --check`にエラーがない
- [ ] GitHub Actions(Validate published articles / Jekyll build / deploy)が成功している
- [ ] 公開後、実URLで表示・リンク・CTAを確認している

## Dev Log Gate(`content_type: devlog`の記事のみ対象)

`content_type: devlog`の記事は「実体験記事」ではないため、上記のインタビュー・事実性の
項目群は適用しない(CLAUDE.mdの最重要ルールの適用除外)。詳細な設計・Factルール・
Security/Privacyフィルタは[docs/devlog-policy.md](./devlog-policy.md)を正本とし、
ここには複製しない。この節ではpublish前の最終チェックポイントのみ列挙する。

- [ ] `source_project`が`config/devlog-projects.yaml`で`enabled: true`かつ`public: true`
- [ ] `source_commits`に列挙されたcommitが、既存の`_articles/`・`drafts/`いずれの記事とも
  重複していない(重複防止)
- [ ] 本文がGitのcommit/変更ファイル/行数から確認できる事実(CONFIRMED_GIT_FACT)のみで
  構成されており、体験・理由・感想を創作していない
- [ ] 本文・frontmatterのいずれにも、secrets・API key・token・password・`.env`内容・
  internal IP・個人情報・Windows固有の絶対パスが含まれていない
- [ ] `_articles/`へは`status: ready`になった段階でのみ配置している(`drafts/`から昇格)
- [ ] `order`が空欄でなく、devlog専用の予約レンジ`9<YYYYMMDD><連番2桁>`の整数値になっている
  (`scripts/validate-site.py`の`check_order_values`が空欄・非整数を検出する)
- [ ] `title`・`primary_keyword`が日本語の自然な検索クエリになるよう見直されている(機械生成の
  ままだとcommit message由来の英語表記が残ることがある。書き換えなくても事実性は損なわれないが、
  SEO上は推奨。詳細は`docs/devlog-policy.md`9節)

## 最終確認

- [ ] 該当する実体験・コード・配線・製品情報の確認が完了している(Dev Logは上記Dev Log Gateで代替)
- [ ] 上記すべてを満たした上でステータスを`ready`に変更してよい
