# PROJECT_PRINCIPLES.md

AI-Tech-Labの執筆・運用原則の索引です。正本は[CLAUDE.md](../CLAUDE.md) / [BRAND.md](../BRAND.md) / [ROADMAP.md](../ROADMAP.md)であり、このファイルはその要点をすばやく参照するための要約＋リンク集です。内容が食い違う場合は正本を優先してください。

## 執筆の絶対ルール

一般論だけの記事は禁止。記事を書く前に必ずインタビューを行う(なぜ作ろうと思ったか / 解決したかった問題 / 失敗 / 改善 / 今ならどう作るか / 使用部品 / おすすめ・非おすすめ部品)。回答が不足する場合は書かずに追加質問する。
詳細: [CLAUDE.md](../CLAUDE.md) 「最重要ルール」

## 事実性・信頼性

ユーザーが回答していない実体験・測定結果・失敗談・使用感を創作しない。未確認情報は断定せず「未確認」「要検証」と明記する。
詳細: [CLAUDE.md](../CLAUDE.md) 「事実性・信頼性」

## 技術・安全ルール

サンプルコードには処理内容がわかるコメントを書き、使用ライブラリ・対応ボード・必要バージョンを明記する。電圧・電流・極性・発熱・ショートの注意点を記載し、5V系と3.3V系の接続時は安全性を確認する。未検証コードは「未実機検証」と明記する。
詳細: [CLAUDE.md](../CLAUDE.md) 「技術・安全ルール」

## アフィリエイト方針

商品紹介は読者の課題解決に必要な場合のみ行い、記事の主目的にしない。実際に使用したものを優先し、未使用の商品を使用済みのように表現しない。誇大広告・ステルスマーケティング的な表現はしない。
詳細: [CLAUDE.md](../CLAUDE.md) 「アフィリエイト方針」/ [BRAND.md](../BRAND.md) 「収益化方針」

## ブランド・トーン&ボイス

やさしく、専門用語には一言説明を添える。「〜しましょう」など読者に伴走する語り口。失敗談も隠さず共有し、上から目線・マウンティングをしない。
詳細: [BRAND.md](../BRAND.md) 「トーン&ボイス」

## 記事ステータス運用

idea → interview → draft → testing → review → ready の順で管理する。実体験・コード・配線・製品情報の確認が完了するまで`ready`にしない。公開直前のチェックは[publish-checklist.md](./publish-checklist.md)を使う。
詳細: [CLAUDE.md](../CLAUDE.md) 「記事ステータス」
